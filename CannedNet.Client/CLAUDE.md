# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **BepInEx 6 IL2CPP plugin** that redirects Rec Room's networking away from official
servers (`ns.rec.net`, Photon) toward a custom "CannedNet" private-server backend. It is a
client-side mod, loaded into the game at runtime — not a standalone application.

## Build

```powershell
dotnet build
```

The output `CannedNet.Client.dll` is the deployable plugin. A post-build MSBuild target
(`DeployPlugin` in the csproj) automatically copies it to `$(GamePath)\BepInEx\plugins\`
after every successful build, so no manual copy is needed.

**The build fails if Rec Room is running** — the game holds a lock on the deployed
`CannedNet.Client.dll`, so the copy step errors (`MSB3027 ... file is locked by RecRoom.exe`).
Note this is *only* the deploy step failing; the compile already succeeded (the `bin\` DLL is
up to date). Close the game and rebuild to actually deploy.

There are **no tests** and no linter — `dotnet build` is the only verification step.

### GamePath is the critical build dependency

`CannedNet.Client.csproj` references **stripped, IL2CPP-interop game assemblies** via
`<GamePath>`. Every `<Reference>` resolves to `$(GamePath)\BepInEx\interop\*.dll`. These
DLLs are generated by BepInEx's IL2CPP proxy generator against a *specific game build* and
are not in the repo, so they must come from a local Rec Room install whose
`BepInEx/interop/` folder has been populated (run the game once under BepInEx to generate it).

`GamePath` is **not hardcoded in the csproj** (so the repo is distributable). It resolves, in
priority order, from: a local `GamePath.props` file (copy `GamePath.props.example` →
`GamePath.props`, which is gitignored), the `RECROOM_PATH` environment variable, or
`dotnet build -p:GamePath=...`. A `ValidateGamePath` MSBuild target fails the build early with
a clear message if `GamePath` is unset or has no `BepInEx\interop` folder — rather than
emitting ~900 unresolved-reference warnings.

## Architecture

`Plugin.cs` is the entry point (`BasePlugin.Load`). It binds all BepInEx config entries,
calls `Harmony.CreateAndPatchAll`, and the Harmony patches under `Patches/` do the actual
redirection. The independent pieces:

1. **`Patches/SendRequestPatch.cs`** — patches `HTTPManager.SendRequest` (BestHTTP).
   Rewrites the host of **any** request under the official root `rec.net` (`ns.rec.net`,
   `api.rec.net`, `cdn.rec.net`, …) to the custom server, preserving the subdomain, port,
   and path: `api.rec.net/foo` → `api.my.new-rec.net/foo`. The replacement root is derived
   from `Plugin.ServerHostname` by parsing its host and stripping a leading `ns.`
   (`GetBaseDomain()`). When `[Advanced] Debug` is on, the prefix also traces each request
   (method, URL, body via `GetEntityBody()`), its response (status + body, via a wrapped
   `Callback`), and the headers actually written to the socket (`CaptureSentHeaders` tees
   BestHTTP's `OnSendingHeaders` — this is the only place the lazily-added `Authorization`
   bearer is visible, so it logs tokens in plaintext). Noisy telemetry endpoints
   (`IsIgnoredForLogging`: `datacollection`, `/api/gamesight/event`) are skipped for logging
   but still rewritten. The host rewrite itself is always active regardless of `Debug`.

2. **`Patches/PhotonPatches.cs`** — postfixes the obfuscated getter that returns Photon
   `AppSettings` (`GPFPFDBGCEK.AMOHMPKKGHL`), overwriting it in place with the custom Photon
   App IDs (from `[Photon]` config), region `us`, UDP, and — in advanced mode — the custom
   Photon NameServer, so multiplayer (Realtime/Voice/Chat) connects to the custom backend
   instead of official Photon.

3. **`Patches/EACPatches.cs`** — neutralizes Easy Anti-Cheat (`RecRoom.AntiCheat.EACManager`):
   forces its readiness check to return `true` and stubs `GenerateChallengeResponse` to echo
   the challenge back base64-encoded, so EAC doesn't block connecting to the private backend.

4. **`Patches/FuckOffTLS.cs`** — prefixes `LegacyTlsAuthentication.NotifyServerCertificate`
   (BouncyCastle) to no-op, disabling server certificate validation so the custom server's
   certs aren't rejected.

5. **`Patches/FileSignaturePatch.cs`** — neutralizes Rec Room's game-file signature check
   (obfuscated type `JAPJPGNBMNM`). The mod's presence perturbs a game file enough that its
   signature no longer matches the signed manifest, throwing
   `JAPJPGNBMNM.HOOLEAJINMJ` ("Signatures don't match!"). The patch postfixes the failure-result
   factory `AOFCCEACNNA.PNEAHABDBHH(Exception)` to instead return the parameterless success
   result `AOFCCEACNNA.JGIHNLEFJEL()`, so the check always passes.

6. **`Patches/GameConfigFlagPatch.cs`** — guards a game-config / feature-flag getter
   (`GOBAHJBPPEM.HJLNMINPFNG`, il2cpp getter `LBPOALIGKJL`) that reads a config-backed
   `Nullable<bool>.Value`. The backend's `/api/gameconfigs/v1/all` doesn't supply that key, so
   the nullable is empty and every read throws `InvalidOperationException` ("Nullable object must
   have a value") — it surfaced via `LeaderboardView`'s scheduled update requeuing forever. The
   prefix returns `false` (feature off) and skips the original. The correct alternative fix is to
   add the missing key to the backend's gameconfigs.

7. **`Plugin.OnSceneLoaded`** — on every scene load, destroys the `[CheatManager]`
   GameObject (`GameRoot/(Startup)(Clone)/Core Systems/[CheatManager]`) if present so it
   doesn't interfere.

### Obfuscated game symbols — the main maintenance hazard

Rec Room ships with obfuscated type/method names that **change between game builds**, and
this is the single biggest source of breakage after a game update. Several patches are bound
directly to these unstable names via `[HarmonyPatch]` attributes, so a renamed symbol throws at
patch time and aborts the whole plugin load — re-find and update the name when that happens:

- `PhotonPatches.cs` targets `GPFPFDBGCEK.AMOHMPKKGHL` — the obfuscated getter returning Photon
  `AppSettings` (historically `PUNNetworkManager.FJOLIPKKIBE`, then `FOMEIIMJMKH`, …; the connect
  path now goes through this getter). It's the static/virtual method whose return type is
  `AppSettings` (the chat variant returns `ChatAppSettings`).
- `EACPatches.cs` targets `EACManager.FJLMLEPOKGE` (the readiness check, a static parameterless
  `bool`) and `EACManager.GenerateChallengeResponse`.
- `FileSignaturePatch.cs` targets `JAPJPGNBMNM.AOFCCEACNNA.PNEAHABDBHH(Exception)` — the failure
  factory of the file-check result type `AOFCCEACNNA`. `JGIHNLEFJEL()` is that type's parameterless
  (success) factory and `JAPJPGNBMNM.HOOLEAJINMJ` is the "Signatures don't match!" exception.
- `GameConfigFlagPatch.cs` targets `GOBAHJBPPEM.HJLNMINPFNG` (a static `bool` getter, il2cpp name
  `LBPOALIGKJL`) — the one that throws `InvalidOperationException` on an unset config `Nullable<bool>`.

**Re-finding a renamed symbol:** decompile the current build's interop stubs with `ilspycmd`
(`dotnet tool install --global ilspycmd`), e.g.
`ilspycmd -t "RecRoom.AntiCheat.EACManager" "$(GamePath)\BepInEx\interop\RecRoom.Rranticheat.Runtime.dll"`.
The interop DLLs encode each method's signature in its `NativeMethodInfoPtr_<name>_<...>_<RetType>_<Params>`
field name, so you can match by signature (e.g. the EAC readiness check is the only static
parameterless `Boolean` method). The interop stubs are *signature-only* — string literals
(hardcoded hostnames, error strings) live in `RecRoom_Data/il2cpp_data/Metadata/global-metadata.dat`
instead and can be found with `grep -a`.

### Config (BepInEx config file, sections in brackets)

- `[Photon]` — `App Id Realtime` / `App Id Voice` / `App Id Chat`: Photon App IDs used in normal mode.
- `[Server]` — `RecNet NameServer Host` (default `https://ns.lapis.codes`): the custom server.
  Used both as the redirect target for `*.rec.net` hosts and as the source of the base domain
  (see `SendRequestPatch.GetBaseDomain()`).
- `[Advanced]` — `Enabled Advanced Settings` gates `Photon NameServer` + `Photon NameServer Port`.
  When advanced mode is on, the Photon patch routes to that custom Photon NameServer (region
  `eu`, port defaults to `4533` if left `0`) with empty App IDs instead of the `[Photon]` App
  IDs (region `us`).

## Conventions

- C# top-level file-scoped namespaces (`namespace CannedNet.Client;`), `net6.0`, `latest` lang version, `AllowUnsafeBlocks`.
- All game-facing types are IL2CPP proxies — use the `Il2Cpp*` variants when interoping with game code (e.g. a request's URI is `Il2CppSystem.Uri`). Plain BCL types still work for plugin-local logic, so both can appear in one file: `SendRequestPatch.cs` parses the config string with `System.Uri` but assigns the game request a new `Il2CppSystem.Uri`.
- Log through `Plugin.Log` (a `ManualLogSource`); existing log lines are informal/debug-style.
